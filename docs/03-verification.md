# 03 验证策略

## 1. 三层验证金字塔

```
        ┌──────────────────────────┐
   板上 │  真实硬件 + ILA + 示波器  │  少量、昂贵、不可替代
        ├──────────────────────────┤
   对拍 │  RTL vs Python 定点模型   │  主力：逐位一致，覆盖全部算法
        ├──────────────────────────┤
   单元 │  协议时序检查（I2S 帧格式）│  基础：边界条件、复位、握手
        └──────────────────────────┘
```

**核心思想：把"结果对不对"交给 Python 黄金模型，把"时序对不对"交给协议模型。**
两条线分开，出问题时能立刻定位是算法错还是时序错。

## 2. 黄金模型对拍（本项目的主要验证手段）

### 2.1 为什么必须是「定点」黄金模型

浮点模型只能验证"算法设计对不对"，不能验证"定点实现对不对"。
本项目的 `scripts/golden/dsp.py` 是**位级复刻**：

| RTL 行为 | Python 对应实现 |
| --- | --- |
| `y = sat24((acc + RND) >>> SH)` | `sat24((acc + RND) >> SH)` |
| `st1' = p1 + st2 - a1*y`（48bit 截断） | `wrap_acc(x*b1 + s2 - y*a1)` |
| 系数 Q2.16 量化 + 饱和 | `quant_coef(c, 18, 16)` |

因此对拍判据是 **`!==`（逐位相等）**，不是"误差小于某个阈值"。

### 2.2 向量生成与对拍流程

```bash
python3 scripts/golden/gen_all.py     # 生成 sim/vectors/*.hex + 系数 ROM
bash scripts/sim/run_iv.sh            # iverilog 跑三条 testbench
```

testbench 会同时把 RTL 实际输出导出到 `sim/vectors/eq_out_rtl.hex`，
可以再用 Python 做二次交叉核对（不依赖 testbench 自身的比较逻辑）。

### 2.3 测试激励设计（覆盖边界）

`gen_all.py` 的三段式输入不是随便凑的：

| 段 | 内容 | 覆盖目标 |
| --- | --- | --- |
| 1 | 单点冲激 | 每个 section 的极点/零点、状态初值路径 |
| 2 | 100/1000/8000 Hz 多音叠加 | 稳态频响、section 级联顺序 |
| 3 | 满量程 1 kHz 方波 + 极值 | **饱和分支**（`ovf_p` / `ovf_n`） |

## 3. 三条 testbench 及其覆盖范围

| testbench | 覆盖 | 判据 | 关键设计点 |
| --- | --- | --- | --- |
| `tb_eq_cascade` | 均衡器算术、系数写端口、FSM | 6000 样本逐位一致 | 每样本间隔 20 clk，验证 `x_ready` 握手 |
| `tb_i2s_loopback` | BCLK/LRCLK 分频比、位对齐、槽对齐 | 双向 0 错 | codec 模型严格按"下降沿发送 / 上升沿采样" |
| `tb_audio_top` | 全链路 + 系数 ROM 装载 + 双 FIFO | 冲激响应逐位一致 | 左声道送 +冲激、右声道送 −冲激，可检出左右声道接反 |

### 3.1 I2S 验证要点

`tb_i2s_loopback` 同时验证两个**独立的**方向，避免"收发同时错所以测试通过"的假阳性：

1. **接收方向**：`i2s_rx` 解出的样本 == codec 模型发出的样本
2. **发送方向**：codec 模型从 `sdout` 解出的样本 == 喂给 `i2s_tx` 的样本
3. **分频比**：两次 `frame_start` 之间的 BCLK 上升沿数必须恰为 `2*SLOT`

## 4. 板级验证方法（上板后）

### 4.1 音频链路延迟实测

**方法**：FPGA 内部产生一个已知的脉冲标记（例如在收到样本时翻转一个 GPIO），
用示波器双通道同时测 `sdin`（模拟输入）和 `sdout`（模拟输出），
直接读出模拟域的端到端延迟。这是唯一能证明"< 1 ms"的硬证据。

### 4.2 用 ILA 观测内部信号

`build.tcl` 使用了 `-flatten_hierarchy none`，保留层次名，可以在
Vivado Hardware Manager 里直接抓：

| 抓取目标 | 层次路径 | 验证内容 |
| --- | --- | --- |
| 系数装载 | `audio_top/u_eq_l/coe` | 换挡时 25 个系数是否整批更新 |
| FIFO 水位 | `audio_top/in_count` `out_count` | 是否出现溢出/欠载 |
| I2S 时序 | `audio_top/bit_idx` `lrclk` | LRCLK 翻转点是否在 MSB 前一拍 |

### 4.3 频响实测

用 PC 播放扫频信号（20 Hz → 20 kHz），FPGA 输出接声卡录音，
用 Python 做 FFT 求传递函数，与 `gen_all.py` 打印的理论频响曲线对比。
**这是"性能数据可直接复现"最直接的形式。**

## 5. 已知陷阱（踩过的坑，务必避免重复）

1. **定点频响评估时 `a0` 必须同步缩放**。用 `1 + a1 z^-1 + a2 z^-2` 评估定点系数会虚报出
   完全错误的误差（本项目曾因此误判 Q2.16 不可用）。
2. **`wait(signal)` 可能在信号还没置位时立刻返回**。等待"忙→闲"必须
   `wait(busy); wait(~busy);`，否则会在配置窗口内就开始灌数据。
3. **握手信号必须与时钟沿选通同周期**。`frame_start` 若比 `bclk_fall` 晚一拍，
   收发端会在错误的沿执行装载（本项目因此整帧丢数据）。
