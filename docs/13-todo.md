## 明确**不做**的

| 想法 | 为什么不做 |
| --- | --- |
| **HDMI 视频*输入*** | 不产生新能力（频谱叠加和现在等价），资源陡增；本板也没有 HDMI IN 通道。详见 [01](01-architecture.md) §8.1<br>（**注意：HDMI *输出* 保留**，见 P1-3） |
| **CEC / HDMI 音频 / HDCP / InfoFrame** | 我们只做 TMDS = DVI 输出，这些 HDMI 辅助协议都不需要 ✓ 大幅简化 |
| **移植真正的 LVGL** | 要放软核 CPU + framebuffer，违背纯 RTL 约束，且丢掉"扫描到哪算到哪"的性能优势 |
| **运行时动态创建控件** | RTL 里没有指针/动态内存，物理上做不到。控件个数综合前定死 |
| **通用布局引擎（flex/grid）** | FPGA 的正确做法是"编译期算好布局 + 参数化"，不是运行时算 |
| **部分刷新（脏矩形）** | 本架构**没有 framebuffer**，每个像素只在被扫描时算一次 —— 已经在做最彻底的局部计算了 |
