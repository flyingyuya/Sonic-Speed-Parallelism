# 01 系统架构

> **定位**：专精的**音频一体化系统** —— 采集 → 均衡 → 频谱分析 → 可视化 → 交互调参，全链路实时。
>
> **不含视频输入/输出链路**。屏幕是"人机交互界面"，不是"视频处理功能"。
> 早期版本曾规划 HDMI 视频流协同，已明确放弃（详见 §8）。

## 2. 时钟域规划

| 时钟域 | 频率 | 来源 | 承载逻辑 |
| --- | --- | --- | --- |
| `clk_sys` | **48 MHz** | MMCM（200 MHz / 4 × 18 = 900 MHz VCO，÷18.75） | I2S 恢复、EQ、FFT、频谱、控制、UART |
| `clk_pix` | **12.5 MHz** | 同一 MMCM（900 / 72） | 显示扫描、极坐标变换、波形读出 |
| BCLK | 3.072 MHz | **外部输入**（WM8960） | 不当时钟用，只由 `i2s_slave_clk` 过采样 |
| `clk_hdmi` | 74.25 MHz | **第二个 MMCM** | HDMI 720p60 像素流水线（规划中） |
| `clk_hdmi_x5` | 371.25 MHz | 同上 | TMDS 5:1 串行化（规划中） |

### 第一个 MMCM 为什么能同时出 48 / 12.5 MHz

```
VCO = 900 MHz
  ÷18.75 = 48    MHz   (clk_sys)
  ÷72    = 12.5  MHz   (clk_pix)
```

48 / 12.5 = 3.84，需要 VCO 同时是二者的整数倍 → **O_sys 必须是 6.25 的倍数**。
900 MHz 让两个分频比都很舒服（18.75 用 `CLKOUT0_DIVIDE_F` 的 1/8 步进，72 是整数）。

### 第二个 MMCM：为什么 HDMI 加不进第一个

`900 MHz / 74.25 MHz = 12.12` **非整数** ✗ 所以必须单独一个 CMT：

```
输入 200 MHz → D=5, M=18.5625 → VCO = 742.5 MHz
                 ÷10 = 74.25  MHz  (1280×720@60 像素时钟)
                 ÷2  = 371.25 MHz  (TMDS 5× 串行化时钟)
   M = 18.5625 = 18 + 4.5/8 ✓ 正好在 MMCM 的 1/8 步进上
```

### 为什么 BCLK 不当时钟域

**WM8960 是 I2S 主**（手册 P56：数字音频接口也从 SYSCLK 派生，MCLK 必须与 BCLK/LRCLK 同源）。

FPGA 侧有两个选择：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 把 BCLK 当全局时钟 | BCLK 域接收 → 异步 FIFO → clk_sys | 多一个时钟域、多一个 BUFG |
| **过采样恢复（本工程选这个）** | `i2s_slave_clk` 在 clk_sys 域检测 BCLK 边沿 | 少一个时钟域，但要注意采样余量 |

**余量核算**：clk_sys 48 MHz / BCLK 3.072 MHz = **15.6 个 clk 每 BCLK**。
BCLK 半周期 163 ns，边沿检测偏差最多 1 个 clk（20.8 ns）✓ 余量充足。

### 为什么不需要 12.288 MHz 音频时钟

早期方案（`i2s_clkgen` 主模式）需要 12.288 MHz 让 BCLK = clk/4 精确整除。
**改成从模式后这个约束消失了** —— `i2s_slave_clk` 靠过采样，只要 clk 明显快于 BCLK 即可 ✓
少一路时钟，MMCM 输出从 3 路降到 2 路。

### 跨时钟域

只有一处：`spec_sync`（音频→显示，柱高快照）和 `wave_buf`（采样缓冲）。
都用**格雷码 + 两级同步器**，`report_cdc` 确认 Unsafe = 0。

## 3. 定点格式

| 信号 | 位宽 | 格式 | 说明 |
| --- | --- | --- | --- |
| 音频样本 `x/y` | 24 bit signed | **Q1.23** | 满量程 ±1.0 |
| 滤波器系数 `b/a` | 18 bit signed | **Q2.16** | 匹配 DSP48E1 的 25×18 乘法器 |
| 累加器 `s1/s2` | 48 bit signed | Q?.40 | 乘积标度 = 23 + 16 = 39 位小数 |
| FFT 数据 | 24 bit signed | Q1.23 | 每级 ÷2 缩放，共 ÷N |
| FFT 旋转因子 | 16 bit signed | Q1.15 | 只存 0~45° 的 1/8 表，其余靠对称 |
| FFT 输出幅度 | 25 bit unsigned | — | `max + 0.4375·min` 近似（不开方） |
| 柱高 | 9 bit unsigned | 0..511 | 由 log2 压缩得到 |
| 颜色 / 波形偏移 | 24 bit / 8 bit | — | 显示用 |

> **系数为什么用 Q2.16 而不是 Q1.17**：Q1.17 的范围是 [−1, 1)，而二阶高架的
> `b0` 会到 2.12，直接削顶（实测频响误差 7 dB）。Q2.16 范围 [−2, 2) 覆盖得住，
> 代价只是 1 个整数位，DSP48 的 18 位字长不变。

**舍入与饱和**：`acc → 右移 16 位（+2^15 四舍五入）→ 饱和到 24 bit`。

## 4. 均衡与频谱：为什么拆成两条通路

原选题设想的「FFT → 调增益 → IFFT」属于 **STFT 频域均衡**，
其**算法固有延迟 = 一个分析窗长**：1024 点 @48 kHz = **21.3 ms**。
这与"实时"直接矛盾，而且是**数学问题，不是实现问题**。

所以拆成两条独立通路：

| 通路 | 实现 | 延迟 | 用途 |
| --- | --- | --- | --- |
| **A. 聆听通路** | 5 段双二阶 IIR 级联（每声道） | 6 周期/样本 ≈ **0.13 µs** | 实际听感上的多段均衡 |
| **B. 分析通路** | 1024 点 FFT → 幅度谱 → 对数压缩 → 60 根柱 | ≈ 21 ms（与聆听通路无关） | 驱动频谱显示 |

> **这条对比本身就是工程结论**：低延迟场景不用 STFT。
> 报告里两个数字都给（IIR：算法固有 0 + 流水 0.13 µs；
> FFT 频域均衡：算法固有 21.3 ms），比只给一个"<1ms"经得起追问。

### 均衡器结构

`eq_cascade`：**单 MAC、时分复用 5 个 section**，每样本 6 个时钟周期。

```
IDLE ──x_valid──▶ CALC(sec0) ─▶ CALC(sec1) ─▶ ... ─▶ CALC(sec4) ─▶ 输出 y, 回 IDLE
```

每个 section 用 Direct-Form-II-Transposed：

```
y[n]  = b0·x[n] + s1
s1'   = b1·x[n] - a1·y[n] + s2
s2'   = b2·x[n] - a2·y[n]
```

**系数表方案**：不做片上浮点/三角运算，而是离线用 Python 生成
`(频段, 增益档位) → 5 个系数` 的 ROM（5 段 × 21 档 = 105 组），
运行时直接切换表项，FPGA 侧零开销、零精度风险。

## 5. FFT 与频谱

**存储式（1 个蝶形时分复用），不是全并行**：

```
1024 点基 2 DIT，单蝶形，in-place，双口 BRAM（实部/虚部各一个 RAMB36）
输入位反转 / 输出自然顺序
每级 ÷2 缩放（10 级共 ÷N，满量程正弦峰值映射到 0.5）
时间：N/2 × LOG2N × 2 = 10240 拍 + 输出 513 拍 = 10756 拍 ≈ 一帧的 1.05%
资源：1004 LUT / 126 FF / 2 BRAM36 / 4 DSP48
```

**为什么不用 parallel/generate**：全并行需要 512 个蝶形 × 4 DSP = **2048 DSP**，
器件只有 240 个。时分复用后只要 4 个，**开销降到 1/500**，而 FFT 只占 1% 帧时间 —— 做快没有任何收益 ✓

**频谱柱高**（`spectrum.v`）：

```
① 频率分组：低频 16 根线性（每根 1 个 bin，覆盖到 703 Hz）
            高频 44 根对数（每 4 根柱一个八度）
            → 因为纯对数时低频前几根柱只覆盖 1 个甚至 0 个 bin，会出现空柱子
② 组内取最大
③ dB 压缩：log2 近似（优先编码器 + 3 位尾数），不用乘法器
            每像素约 0.188 dB，满量程约 96 dB 动态范围
④ 峰值保持 + 每帧线性衰减
```

## 6. 显示：扫描到哪算到哪

**没有 framebuffer，没有渲染状态机**：

```verilog
// disp_mix.v —— 对每个像素，
rgb = f(x, y, bars, hue);     // 纯组合逻辑，被扫描时才计算
```

参考工程 Music-Spectrum 用了 400 行嵌套计数器的渲染状态机 + 像素流 FIFO。
**它这么做的唯一理由是背景图来自 SD 卡，必须流式取回才能混合。**
我们背景用组合逻辑算，不需要那一套 ✓

### 三种视图合成

```
┌──────────────────────────────────────────────┐
│              ╭──────────╮                    │
│             (  ◉ 60 辐条 )                   │  极坐标：64 扇区 / 零乘法求角度
│  ~~~~~~~~~~~~~~~波形~~~~~~~~~~~~~~~~~~~~~~~~~ │  波形：中线固定 y=136
├──────────────────────────────────────────────┤
│   ▁▃▅▇█▇▅▃▁   柱状频谱（60 根 × 8 px）         │  柱状：480/60 = 8 → x[8:3]
└──────────────────────────────────────────────┘
绘制顺序：背景 → 柱状 → 波形 → 极坐标（最上层）
```

**几何全程免乘法**：
- 柱下标 `480/60 = 8` → `x[8:3]`
- 极坐标角度 → `min*64` 与 `max*{6..52}` 比较（斜率近似，非除法）
- 极坐标半径 → `dx²+dy²` 与 `R²` **比平方**（精确，2 个 DSP）

## 8. 输入/输出方向：视频输入放弃，HDMI 输出保留

### 8.1 放弃「视频流输入」

项目初期曾规划：HDMI 输入 → 视频预处理 → 频谱 Overlay → HDMI 输出，
并预留了 74.25 MHz 视频域和 TMDS 收发。

**视频输入已明确放弃**，理由：

| 理由 | 说明 |
| --- | --- |
| **不产生新能力** | 把频谱叠加到视频上，本质还是"显示频谱"，和现在的液晶方案功能等价 |
| **资源与复杂度陡增** | TMDS RX + 行缓存 + 时序对齐，至少 2000+ LUT 和 6~10 个 BRAM |
| **本板无 HDMI 输入通道** | 原理图只有 `HDMI OUT` 页，没有 `HDMI IN` |

### 8.2 保留「HDMI 输出」—— 而且是**解耦**的第二路显示

**动机**：480×272 的液晶屏太小，演示时不够醒目。
把液晶当作**交互界面**，HDMI 当作**可视化展示大屏**，两者**同步更新**。

```
                        ┌──────────────────────────┐
   柱高 / 波形 / 配色 ──▶│     render_core          │
   （来自 ui_ctrl）       │  (x, y, W, H) → RGB888   │
                        │  背景→柱状→波形→极坐标    │
                        └────────┬─────────────────┘
                                 │  同一套渲染逻辑
                    ┌────────────┴────────────┐
                    ▼                         ▼
          ┌──────────────────┐      ┌──────────────────┐
          │  lcd_timing      │      │  hdmi_timing     │
          │  480×272 @12.5M  │      │  1280×720 @74.25M│
          └────────┬─────────┘      └────────┬─────────┘
                   ▼                         ▼
              LCD 直连              tmds_encoder ×3 + OSERDES
              （交互界面）            （可视化展示）
```

**为什么"解耦"能成立**：`disp_mix` 本来就是 `(x, y) → RGB` 的**纯组合函数** ✓
把尺寸参数化，就能实例化两次 ✓ 两个输出的宽高比都是 16:9，布局常数只需按比例缩放 ✓

| 共用 | 各自 |
| --- | --- |
| 频谱柱高（`spec_sync`） | 时序发生器（`lcd_timing` / `hdmi_timing`） |
| 波形缓冲（`wave_buf`） | 输出编码（直连 / TMDS） |
| 配色与视图开关（`ui_ctrl`） | 画布尺寸（480×272 / 1280×720） |
| 背景 / 极坐标 / 柱状逻辑 | |
| **UART / 按键的设置自动同步到两路** ✓ | |

**硬件基础**（原理图第 14 页已核实，见 [06](06-board-resources.md) §6）：
板上 HDMI 是 **FPGA 差分对直连**（51Ω 串阻 → 连接器 J5），**没有发送芯片**。
所以 TMDS 编码必须自己做 —— 好消息是它是**纯组合逻辑**，约 150 LUT/通道，可手写 ✓

| 需要 | 纯 RTL 实现 |
| --- | --- |
| TMDS 8b/10b | 纯组合（XOR/XNOR + DC 平衡）✓ |
| 5:1 串行化 | `OSERDESE2`（**器件原语**，与 `MMCME2_BASE`/`IBUFDS` 同类，不是 IP 核） |
| 差分输出 | `OBUFDS` |

> **只做 TMDS（不要 CEC / 音频通道 / HDCP / InfoFrame）= DVI 输出** ✓
> HDMI 显示器的 DVI 兼容模式都接受，大幅简化 ✓

**分辨率分期**（`OSERDESE2` 需要像素时钟 × 5）：

| 分辨率 | 5× 时钟 | 难度 |
| --- | --- | --- |
| 800×600@60 | 200 MHz | ✅ 容易 —— **建议从这里起步** |
| 1280×720@30 | 185.6 MHz | ✅ 容易 |
| 1280×720@60 | **371.25 MHz** | ⚠️ 有挑战 —— 目标 |
| 1920×1080@60 | 742.5 MHz | ❌ 做不到 |

需要**第二个 MMCM**（`D=5, M=18.5625 → VCO 742.5 MHz → ÷10=74.25 / ÷2=371.25`）✓
板上有 6 个 CMT，用掉 2 个还剩 4 个 ✓

### 8.3 新定位

**专精的音频一体化系统**，双路显示：

```
采集 → 均衡（聆听通路）
     → FFT → 频谱柱高 ──┬─▶ LCD 480×272（交互界面 + 预览）
                        └─▶ HDMI 720p（可视化展示大屏）
                            ↑
              按键 / UART 的设置同时作用于两路
```

把「采集→均衡→分析→可视化→交互」这条链做深做透，而不是横向铺功能。
