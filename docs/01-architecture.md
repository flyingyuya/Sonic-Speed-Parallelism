# 01 系统架构

## 2. 时钟域规划

| 时钟域 | 频率 | 来源 | 承载逻辑 |
| --- | --- | --- | --- |
| `clk_sys` | 100 MHz | 板上晶振 | 控制寄存器、UART、状态机 |
| `clk_audio` | 12.288 MHz | MMCM（100 MHz × N / M） | I2S 收发、均衡器、FFT |
| `clk_pix` | 74.25 MHz | MMCM | 1080p30 视频流水线、Overlay |
| `clk_pix_x5` | 371.25 MHz | MMCM | TMDS 5 倍过采样（若用 OSERDES 则用 371.25 MHz） |

**为什么音频用 12.288 MHz**：12.288 MHz = 48 kHz × 256。I2S 的 BCLK = 12.288/4 = 3.072 MHz = 48 kHz × 64，
LRCLK 由 BCLK 整数分频得到，**采样率精确为 48 kHz，无小数分频抖动**。整条音频链路都在这个域内，
不需要任何跨时钟域处理；同时 12.288 MHz / 48 kHz = **256 个时钟/样本**，足够时分复用跑 5 段双二阶（约 6 周期）
加上 1024 点 FFT（约 2000 周期/帧，远小于 256×43 = 11008 周期/帧）。

**为什么不用 100 MHz 直接分频**：100/3.072 = 32.55 非整数，小数分频会给 LRCLK 带来 ±10 ns 抖动，
直接恶化 ADC/DAC 的采样抖动（SNR）。用 MMCM 生成 12.288 MHz 是干净解。

## 3. 定点格式

| 信号 | 位宽 | 格式 | 说明 |
| --- | --- | --- | --- |
| 音频样本 `x/y` | 24 bit signed | Q1.23 | 满量程 ±1.0 |
| 滤波器系数 `b/a` | 18 bit signed | Q1.17 | 正好匹配 DSP48E1 的 25×18 乘法器 |
| 累加器 `s1/s2` | 48 bit signed | Q?.40 | 乘积标度 = (Q1.23 × Q1.17) 的小数位 23+17=40 |
| 频域幅度 | 24 bit unsigned | 对数 dB 压缩后 | 送视频域 |

**舍入与饱和**：`acc → 右移 17 位（+2^16 四舍五入）→ 饱和到 24 bit`。
右移量恒等于 `CW-1 = 17`，与数据位宽无关，便于参数化。

## 4. 音频处理链路选择：为什么是「双二阶 + FFT 双通路」

原选题描述里的「FFT → 调增益 → IFFT」属于 **STFT 频域均衡（WOLA / overlap-add）**，
其**算法固有延迟 = 一个分析窗长**。1024 点 @ 48 kHz = **21.3 ms**，这与「端到端延迟 < 1 ms」的目标直接矛盾。
这不是实现问题，是数学问题，任何方案都无法绕过（除非窗长 ≤ 48 点）。

因此本设计拆成两条独立通路，**两者并行、互不阻塞**：

| 通路 | 实现 | 延迟 | 用途 |
| --- | --- | --- | --- |
| **A. 聆听通路**（主） | 5 段双二阶 IIR 级联，时分复用 MAC | 6 周期 @12.288 MHz ≈ **0.5 µs**，端到端 < 100 µs | 实际听感上的多段均衡 |
| **B. 分析通路** | 1024 点 FFT → 幅度谱 → 对数压缩 → 32 根柱 | ≈ 21 ms（与音频通路无关） | 驱动视频频谱 Overlay |

同时保留 **C. 频域均衡模式（可切换，用于对比演示）**：把通路 B 的 FFT 结果乘上频点增益后做 IFFT +
重叠相加，直接复用同一套 FFT 蝶形单元，形成「同一硬件、两种均衡算法」的对比实验。
这条通路延迟 21 ms，作为**对照数据**写进报告——恰好体现「为什么低延迟场景不用 STFT」的工程判断。

> 竞赛材料建议这样写实测数据：
> `IIR 均衡：端到端 68 µs（算法固有 0）+ 硬件流水 0.5 µs`；
> `FFT 频域均衡：算法固有 21.3 ms + 硬件流水 0.5 µs`。
> 两个数字都给，比只给一个「<1ms」经得起评委追问。

## 5. 均衡器结构

`eq_cascade`：**单 MAC、时分复用 5 个 section**，每样本 6 个时钟周期。

```
IDLE ──x_valid──▶ CALC(sec0) ─▶ CALC(sec1) ─▶ ... ─▶ CALC(sec4) ─▶ 输出 y, 回 IDLE
      xcur = x_in          xcur = y(sec0)   ...
```

每个 section 用 Direct-Form-II-Transposed：

```
y[n]  = b0·x[n] + s1
s1'   = b1·x[n] - a1·y[n] + s2
s2'   = b2·x[n] - a2·y[n]
```

- 每周期只需 **3 个乘法器**（b0·x、b1·x、a1·y）+ 1 个并行（b2·x、a2·y）共 5 个乘法，5 个 section 共用同一套运算器 → 资源占用与 section 数无关
- 反馈环不在同一周期内闭合（section 之间串行、section 内部每样本只算一次），无时序压力
- 系数放在 25×18 bit 寄存器组，由控制域写入，支持运行中实时调参

**参数表方案**：不做片上浮点/三角运算，而是离线用 Python 生成
`(频段, 增益档位) → 5 个系数` 的 ROM 表（5 段 × 21 档增益 = 105 组 × 5 系数），
运行时按键/串口直接切换表项，FPGA 侧零开销、零精度风险。

## 6. 视频域（阶段二）

- 1080p30: 像素时钟 74.25 MHz，行 2200 × 帧 1125
- HDMI 输入：若板上是 ADV7611/IT6802 之类，走并行 RGB/YUV422 → 转 RGB888
- Overlay：在每行的有效区间，用行计数器判断是否落在柱状图区域，用柱高 ROM/B RAM 比较决定叠色
- HDMI 输出：TMDS 编码 + `OSERDESE2`（5:1 或 10:1），XC7A100T 有足够 OSERDES 资源

| 模块 | DSP48 | BRAM36 | 备注 |
