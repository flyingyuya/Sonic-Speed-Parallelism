# HDMI SD 图片背景方案（RGB332 8 位色）—— ⛔ 已弃用

> **结论：这个方案上板实测失败。** 256 色在二次元渐变图上色带太重，观感不可接受。
>
> **实际采用的方案见 `docs/12-display-design.md` §X**：
> 帧缓冲 480×272 RGB565（LCD 1:1 满屏）+ 另一份 320×180 RGB565（HDMI 中心裁剪后 2× 放大）
> ⟹ BRAM 100.5/135（74%）✗ `clk_sys` +1.47 ns ✗ 全彩无色带。
>
> 本文保留作"走错的路"的记录：**当 "降色深" 和 "降分辨率" 二选一时，
> 对图片素材而言降分辨率（略糊）比降色深（色带）的观感代价小得多。**

> 已经把方案验证到"RTL 能编过、只差 TB 更新"的程度，但因为 `disp_top`
> 的 TB 有 400+ 颜色判据要同步改，一次性做完风险较高 ⟹ 回退后把方案固化在这里。

---

## 1. 为什么用 8 位色

| 方案 | 帧缓冲 | BRAM | 时序 | 结论 |
|---|---|---|---|---|
| 480×272 × 16 位（现状）| 2.09 Mb | 58 块 | ✅ | 当前方案 |
| 640×360 × 16 位 | 3.69 Mb | 103 块 | ❌ **98% 占用 ⟹ `clk_sys` -1.092 ns ⟹ place_design 失败** | 不可行 |
| **640×360 × 8 位（RGB332）** | **1.84 Mb** | **52 块** | **预计 ~82/135 = 61% ✓** | **目标方案** |

## 2. RGB332 格式与展开

```
1 字节 = RRR GGG BB   （8×8×4 = 256 色）

展开到 RGB888（位重复 ⟹ 比补零亮）：
  R8 = {R3, R3, R3[2:1]}
  G8 = {G3, G3, G3[2:1]}
  B8 = {B2, B2, B2, B2}
```

⚠️ 二次元渐变图会有**明显色带**。缓解办法：在 `mkimage.py` 里加 4×4 Bayer
有序抖动（PC 端，零 RTL 改动），把色带打散成噪点。

## 3. 一份数据两个屏

```
frame_buf 640×360 @ 8 位（双读口：clk_pix 给 LCD、clk_hdmi 给 HDMI）
  · HDMI ⟹ FB_X0=0,  FB_Y0=0    1:1 全屏
  · LCD  ⟹ FB_X0=80, FB_Y0=44   裁中心 480×272（(640-480)/2, (360-272)/2）

区域外（LCD 的 x/y 超出图片范围时不可能发生；HDMI 全屏都覆盖）
  ⟹ fb_inside=0 ⟹ 回落到程序化背景
```

## 4. 要改的文件（已试过，能编过）

| 文件 | 改动 |
|---|---|
| `rtl/video/frame_buf.v` | 加 `DW` 参数（8）；加第二个读口 `rd2_*`（真双口，不增 BRAM） |
| `rtl/video/sd_img_load.v` | `DW=8` ⟹ **一个字节一个像素**，去掉"两字节配对" |
| `rtl/video/disp_top.v` | 加 `FB_W/FB_H/FB_X0/FB_Y0` 参数；`fb_rgb` 8 位 + RGB332 展开；读地址按偏移算 + `fb_inside` 判定 |
| `rtl/top.v` | `sd_img_load #(.W(640),.H(360),.DW(8))`；`frame_buf #(.W(640),.H(360),.DW(8))` + 双读口接线；LCD 传 `(80,44)`、HDMI 传 `(0,0)`；HDMI 的 `cfg_bg_src` 接 `ui_bg_src & load_done` |
| `scripts/sdcard/mkimage.py` | `LCD_W/LCD_H = 640,360`；RGB565 ⟹ RGB332 |

## 5. ⚠️ 必须先更新的 4 个 TB（这是上次没做完的部分）

| TB | 要改什么 |
|---|---|
| `tb_frame_buf.v` | 图案从 16 位改 8 位；顺便测第二个读口 |
| `tb_sd_img_load.v` | 喂字节的方式从"两字节一像素"改"一字节一像素"；期望图案同步 |
| `tb_disp_top.v` | **参考模型的 `fb_rgb` 8 位 + RGB332 展开**；`fb_addr` 按偏移算 |
| `tb_top.v` | 如果有 fb 相关判据，同步 |

**⚠️ `tb_disp_top` 有 400+ 颜色判据 ⟹ 改参考模型 + 期望值要一起做，
   而且要有"改完在旧 RTL 上会红"的验证，否则可能两边一起错。**
