## 定位说明

项目初期设想的「音视频协同（**视频流采集** + 频谱 Overlay + HDMI 输出）」中，
**视频输入已明确放弃，HDMI 输出保留**（作为解耦的第二路显示）。
改为**专精的音频一体化系统 + 双路显示**。理由见 [01-architecture.md](01-architecture.md) §8。

**新定位下的一条链**：
```
采集 → 均衡（聆听通路） → 频谱分析（分析通路） → 可视化（三视图） → 交互调参
                                                    │
                                        ┌───────────┴───────────┐
                                        ▼                       ▼
                                  LCD 480×272             HDMI 720p（规划）
                                  （交互界面 + 预览）       （可视化展示大屏）
```

**视频输入放弃，HDMI 输出保留**，两者完全解耦（详见 [01](01-architecture.md) §8）。

| 任务 | 交付物 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| I2S 收发 | `rtl/audio/i2s_rx.v` `i2s_tx.v` | 双向闭环 0 误码 | ✅ |
| I2S **从模式**时钟恢复 | `rtl/audio/i2s_slave_clk.v` | 300 帧、相位全程漂移、双向 0 误码 | ✅ |

| 链路整合 | `rtl/audio/audio_top.v` | 端到端冲激响应逐位一致 | ✅ |
| 定点黄金模型 | `scripts/golden/` | numpy 实现，无 scipy 依赖 | ✅ |

**阶段一实测（仿真）**

| 指标 | 数值 |
| --- | --- |
| 均衡器处理延迟 | 6 clk @48 MHz = **0.125 µs** |
| 端到端链路延迟 | 9 clk = **0.19 µs** |
| 单样本处理周期 | 6 / 1000（占用率 0.6%） |
| 频响最大定点误差 | **0.089 dB**（20 Hz–20 kHz 全频段扫描） |
| 冲激响应逐位一致性 | 左右声道各 **256/256** |

> **关键结论**：均衡器算法固有延迟为 **0**（IIR 逐样本处理，无分帧），
> 端到端 0.19 µs 全部是硬件流水延迟。
> 对照：如果改用 STFT 频域均衡，算法固有延迟 = 窗长 = **21.3 ms**（1024 点 @48 kHz）。

## 阶段二：分析与可视化 ✅

### 2.1 FFT 子系统 ✅

| 模块 | 实测 | 验证方式 |
| --- | --- | --- |
| `fft_twiddle_rom.v` | 195 LUT | 用量化表跑 O(N²) 直接 DFT 与 `numpy.fft` 对比，误差 2.9e-06 |
| `fft_addr_gen.v` | 35 LUT | **穷举 5132 组**（含 q/p 只差 stage 位的结构断言） |
| `fft_butterfly.v` | 472 LUT + 4 DSP | 621 组逐位对拍 |
| `fft_core.v` | **1004 LUT / 126 FF / 2 BRAM36 / 4 DSP48** | **2048 个频点逐位一致**，0 丢样本 |

**关键数据**：
- 1024 点，单蝶形时分复用，**开销是"全并行方案"的 1/512**
- 每帧 10756 拍 = 一帧时间的 **1.05%**
- 稳态延迟：输出幅度 `|X| ≈ max + 0.4375·min`（±0.75 dB，永远偏高）
- **WNS +2.541 ns** @48 MHz

### 2.2 频谱柱高 ✅

`rtl/audio/spectrum.v`：512 个 bin → 60 根柱

- 分层分组：低频 16 根线性（每根 1 个 bin）+ 高频 44 根对数（约 8.8 根一个八度）
- dB 压缩用**优先编码器 + 3 位尾数**，零乘法器
- 峰值保持 + 每帧线性衰减
- 验证：**穷举 512 个 bin**，与独立抄写的边界表逐点一致

### 2.3 显示链 ✅

| 模块 | 实测 | 验证方式 |
| --- | --- | --- |
| `lcd_timing.v` | 56 LUT / 47 FF | **七项守恒检查**（一帧 150150 拍 / 130560 个有效像素） |
| `polar_map.v` | 2 DSP + 约 200 LUT | 扫遍 **49920 个像素**与 `$atan2` 逐点比对 |
| `wave_buf.v` | 1 BRAM36 | 双时钟 + 格雷码，10 帧无撕裂 |
| `disp_mix.v` / `bg_src.v` | 纯组合 | **130560 个像素逐点比对** |

**架构选择**：**扫描到哪算到哪**，无 framebuffer、无渲染状态机。
参考工程的 400 行渲染状态机存在的唯一理由是背景图来自 SD 卡必须流式取回 —— 我们的背景用组合逻辑算。

### 2.4 交互 ✅

| 模块 | 实测 | 验证方式 |
| --- | --- | --- |
| `key_debounce.v` | 48 LUT | 带抖动的按键只识别 1 次；纯抖动不产生脉冲 |
| `ui_ctrl.v` | 约 200 LUT | 7 项：默认值/写端口/预设轮转/回绕/自动循环 |
| `uart_rx.v` / `uart_tx.v` | 约 180 LUT | **回环 256 个字节**（含 0x00/0xFF 边界）全部原样收到 |
| `cmd_proc.v` | 约 250 LUT | ASCII 命令解析 + 20 字节回执逐字节核对 |

**设计要点**：按键 / UART / （预留）触摸 **汇到同一个寄存器组**，显示链完全不知道是谁改的。

### 2.5 WM8960 上电配置 ✅

`rtl/wm8960/`：20 条寄存器，I2C 逐字节验证

- PLL：24 MHz → 12.288 MHz（datasheet Table 45 有现成一行）
- **`CLKSEL=1` 必须最后一条**：切过去之前 PLL 必须锁定
- 每条之间留 1 ms，`PLLEN=1 → CLKSEL=1` 实测间隔 **9.649 ms**
