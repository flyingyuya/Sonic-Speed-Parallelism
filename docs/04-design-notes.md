# 04 关键设计决策与踩坑记录

> 这份文档记录"为什么这么设计"以及"哪些坑踩过"。
> 竞赛答辩时评委最常问的就是"你为什么这么做"，问题答案基本都在这里。

---

## 决策 1：为什么放弃 HLS，走纯 RTL

- Vitis HLS 有 CLI（`vitis_hls`）但没有 GUI，`csim`/`csynth` 的迭代反馈远不如直接写 RTL 直观
- 音频均衡器是**强反馈、低并行度、状态相关**的结构，HLS 生成的调度往往反而更差
- 纯 RTL 才能精确控制**延迟**——而本项目的核心卖点就是延迟
- 副作用：所有算法必须有黄金模型兜底，反而让验证更严谨

## 决策 2：定点格式选 Q2.16 而不是 Q1.17（**代价最大的一次踩坑**）

**问题**：18 bit 有符号系数，直觉上写成 Q1.17（比例 2⁻¹⁷）。
结果双二阶的 `b1`/`a1` 典型值达 **−1.984**，超出 Q1.17 的范围 `[−1, 1)`，被削顶到 −1.0，
滤波器直接失效——实测全频段最大频响误差 **7.0 dB**，而单段测试甚至出现 **+87 dB** 的荒谬结果。

**根因**：混淆了"18 bit 有符号"与"Q1.17"。
18 bit 有符号 + 比例 2⁻¹⁷ 的范围是 `[−1, 1)`，即 **Q0.17**；
要覆盖 `[−2, 2)` 必须用比例 2⁻¹⁶（**Q2.16**）。

**修正后实测**：

| 系数格式 | 范围 | 最大频响误差 | 是否削顶 |
| --- | --- | --- | --- |
| Q1.17 (18bit) | [−1, 1) | **7.0 dB** | 是（14 项越界） |
| Q2.16 (18bit) | [−2, 2) | **0.089 dB** | 否 |
| Q2.23 (25bit) | [−2, 2) | 0.0008 dB | 否 |
| Q4.27 (32bit) | [−8, 8) | 0.0001 dB | 否 |

**结论**：24 bit 数据（Q1.23） × 18 bit 系数（Q2.16），1 个 DSP48E1 一次乘法，
正好匹配其 25×18 乘法器。误差 0.089 dB 远低于人耳 0.3 dB 可闻阈值。

**防御措施**：`dsp.py` 里加了 `check_coef_range()`，任何系数越界时
`gen_all.py` 会直接 `SystemExit`，不会悄悄生成一个坏掉的 ROM。

## 决策 3：滤波器结构 — 一阶低架 + 二阶 peaking，而不是二阶低架/高架

**问题**：最初用 RBJ Cookbook 的二阶低架（100 Hz）+ 二阶高架（8 kHz）：

1. **二阶低架在近 DC 处条件数极差**。其分子在 DC 附近正比于 `w0²`（≈1.7e−4），
   而系数本身量级为 1~2，等于要求 18 bit 系数提供 ~24 bit 的有效精度——
   物理上做不到，实测最差频响误差 **1.4 dB**。
2. **二阶高架在 fs=48 kHz、f0=8 kHz 时 `b0` 达 2.12**，超出 Q2.16 范围。

**修正**：

- band0 换成**一阶低架**：分子正比于 `w0`（≈1.3e−2），条件数好 40 倍 → 误差降到 0.09 dB
- band4 换成**二阶 peaking**：peaking 的 DC/Nyquist 增益恰为 1，系数自然落回 `[−2, 2)`
- 一阶滤波器不需要新结构：二阶双二阶令 `b2 = a2 = 0` 即退化为一阶，RTL 零改动

**全表扫描结果**：5 段 × 21 档共 105 组系数，`max|c| = 1.9529`，无一项越界。

## 决策 4：为什么音频链路跑在 12.288 MHz 单时钟域

12.288 MHz = 48 kHz × 256，好处是三重的：

1. **采样率精确**：BCLK = 12.288/4 = 3.072 MHz = 48 kHz × 64，LRCLK 由 BCLK 整数分频得到，
   无小数分频抖动。若直接用板上 100 MHz 分频，100/3.072 = 32.55 非整数，
   小数分频会给 LRCLK 带来 ±10 ns 抖动，直接恶化 ADC/DAC 的采样抖动（SNR）。
2. **零跨时钟域**：I2S 收发、均衡器全在同一域内，不存在亚稳态风险，
   也不需要为音频路径做 CDC。
3. **算力充足**：12.288 MHz / 48 kHz = **256 clk/样本**。
   均衡器只用 6 个（占用率 2.3%），
   1024 点 FFT 每帧需约 2000 周期，而一帧有 256 × 1024 = 262144 周期（占用率 0.8%）。

**代价**：需要一个 MMCM 产生 12.288 MHz。这在用 HSE 晶振的板子上完全不是问题。

## 决策 5：收发两侧都必须加 FIFO

最初想把 `i2s_rx` 直连 `i2s_tx`（不加 FIFO）：
RX 在帧尾（`bit_idx = 63`）才吐出样本，而 TX 必须在下一帧起点装载，
中间只有 **2 个 BCLK 周期**（DIV=2 时 4 个 clk）的余量，而均衡器要 6 个 clk —— **余量不足**。

FIFO 解决三件事：

1. 把"帧节拍"（256 clk 一次）和"处理节拍"解耦
2. 吸收系数装载期间（75 clk ≈ 0.29 个样本）的样本堆积
3. 输出 FIFO 空时 `data_en = 0`，TX 保持上一帧而不是输出零，**避免欠载爆音**

## 决策 6：延迟指标必须诚实拆分

原选题写的"端到端延迟 < 1 ms"与"FFT + 增益 + IFFT"是**互相矛盾**的：
STFT 频域均衡的算法固有延迟 = 一个分析窗长，1024 点 @48 kHz = **21.3 ms**，
这是数学决定的，任何实现都绕不过去。

**解决方案**：拆成两条独立通路，两个数字都给：

| 通路 | 算法固有延迟 | 硬件流水延迟 | 端到端 |
| --- | --- | --- | --- |
| A. 聆听通路（5 段双二阶 IIR） | **0**（逐样本处理，不分帧） | 0.73 µs | **0.73 µs** |
| B. 分析通路（1024 点 FFT，驱动频谱动画） | 21.3 ms | ~0.2 ms | ~21.5 ms |

这样写的好处：< 1 ms 的指标**真实成立**，而且顺带展示了
"为什么低延迟场景不用 STFT"的工程判断——这是加分项，不是减分项。

## 踩坑记录（按发现顺序）

### 坑 1：`frame_start` 比 `bclk_fall` 晚一拍
`i2s_clkgen` 里 `frame_start` 最初是寄存器输出，而 `bclk_fall` 也是寄存器输出，
两者相差一拍 → 收发端在错误的沿执行装载 → **整帧数据全零**。
**修正**：`frame_start`/`half_start` 改为组合输出
`assign frame_start = bclk_fall & (bcnt == NLAST);`

### 坑 2：LRCLK 分频比错一倍
最初写 `if (bcnt == NLAST) lrclk <= ~lrclk;` —— bcnt 走 0..63，
于是 LRCLK 半周期变成 64 个 BCLK 而不是 32 个。
**修正**：LRCLK 由 bit_idx 直接译码：`lrclk <= (bcnt_nxt >= SLOT);`

### 坑 3：TX 在半帧处误重载
因为 `frame_start` 每个 LRCLK 翻转都脉冲一次，TX 在右声道起点又把整帧重载了一遍，
右声道数据被左声道覆盖。**修正**：区分 `frame_start`（整帧起点）与 `half_start`（右声道起点），
只有 `frame_start` 允许重载。

### 坑 4：系数装载 FSM 中途换档
`cfg_load` 处理逻辑里直接写 `gain_reg <= band_gain`。
如果在装载**进行中**收到新请求，`gain_reg` 会在装载途中改变，
导致前几个系数用旧档、后几个用新档。
现象极具迷惑性：**只有 band0 的系数是错的**（因为它是第一批被读出的）。
**修正**：请求只置 `dirty`，`gain_reg` 在 `ST_IDLE → ST_ADDR` 的瞬间整批锁存。

### 坑 5：testbench 里 `wait(running)` 在上电时就返回
`running = ~(cfg_busy)`，复位后第一轮装载完成时 `running` 已经是 1。
TB 发出 `cfg_load` 后立刻 `wait(running)`，在那一拍 `dirty` 还没置位，
于是等到了旧的 `running=1` 就往下走，冲激落进了配置窗口。
**修正**：`wait(cfg_busy); wait(running);` —— 先等忙起来，再等忙落下。
**这条要写进所有上板控制软件里**：写配置后必须确认 `cfg_busy` 起来过。

### 坑 6：频响评估函数漏乘 `a0`
用定点系数算频响时写成 `(b0+b1z+b2z²)/(1+a1z+a2z²)`，
但定点系数的 `a0` 其实是 `2^CF`（65536），漏乘导致分母小 65536 倍，
虚报出 **−187 dB** 的荒谬误差，差点误判 Q2.16 不可用。
**修正**：`a0 = float(1 << CF)`。
**教训**：黄金模型自己也要被验证——用"定点误差应该随精度提高而单调下降"作为 sanity check。
